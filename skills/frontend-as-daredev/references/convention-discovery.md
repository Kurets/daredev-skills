# Extending these conventions

Follow `code-as-daredev` for applying and extending conventions. In addition:

1. Inspect the project's dependencies, JSX runtime, formatting configuration, aliases, and relevant code before editing.
2. Make the smallest relevant change. Follow the project's formatter rather than copying indentation or quote choices from examples.
3. Do not assume a build performs type checking.
4. Do not infer choices of state management, testing libraries, localization tooling, design systems, or project structure from their presence in one repository.
5. Update the repository skill on approval. Update an installed copy only when installation or synchronization is authorized; repository-only setup must remain repository-only.
6. Do not reintroduce declined proposals unless the user asks to reconsider: a personal singleton convention; a preference for accessible, user-facing queries in component tests; an explicit button-type convention; preferring derived values over synchronized duplicate state.
